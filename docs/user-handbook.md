# Реактив CRM — руководство пользователя и карта продукта

Это руководство описывает **текущий интерфейс проекта**, а не правила конкретной компании. Оно предназначено владельцу небольшой компании, сотрудникам семи стартовых ролей и команде, которая получает исходный код для развёртывания и проверки. Технические команды запуска находятся в [README](../README.md) и [инструкции по развёртыванию](deployment.md); пошаговые критерии приёмки — в [чек-листе](manual-acceptance-small-team.md).

## Что делает CRM

«Реактив CRM» связывает продажу химической продукции с закупкой и исполнением. Работа начинается с клиента и его потребности, затем проходит через запросы поставщикам, квоты и проверку товара, расчёт, коммерческое предложение (КП), принятие клиентом количества, счёт, оплату, согласование и поставку. Задачи, история изменений, вложения и обсуждения сохраняют контекст сделки. Для небольшой команды один человек может совмещать роли; при этом доступ определяется назначенными правами.

CRM хранит операции и формирует документы. Она **не отправляет КП и запросы поставщикам по электронной почте сама**: пользователь скачивает файл, передаёт его выбранным каналом и отдельно отмечает отправку. Заявленная оплата также не равна поступившим деньгам: её должен подтвердить сотрудник с финансовым правом. Настройка финансового профиля не является юридическим или налоговым заключением — ставки и формулы задаёт и проверяет компания.

### Визуальный язык текущего интерфейса

Название в интерфейсе — **«Реактив CRM»**, знак — стилизованная колба. Тёмная боковая панель `#202233` задаёт навигацию, фиолетовый `#7960d6` выделяет действия и фокус, светло-зелёный `#c7ed89` — главный призыв к действию, общий светлый фон — `#f6f7fa`. Основной шрифт — **Manrope Variable**. Это описание реализованного UI, **не утверждённый фирменный стиль компании**; при передаче продукта другой команде эти цвета и знак можно использовать для узнаваемости экранов и иллюстраций руководства.

## Основные понятия

| Понятие | Значение в CRM |
|---|---|
| Контрагент | Клиент, поставщик или организация обоих типов. Контакты и звонки связаны с его карточкой. |
| Организация продавца | Юридическое лицо вашей компании, от имени которого оформляется заявка и документы; реквизиты вводятся в «Настройках». |
| Заявка | Работа по конкретному запросу клиента. Содержит позиции, документы, оплаты, исполнение и историю. |
| Позиция потребности | Исходное наименование, CAS, количество, единица, чистота и фасовка, сообщённые клиентом. Изменение создаёт редакцию. |
| Товарный вариант | Запись номенклатуры с производителем, характеристиками и результатом проверки. |
| Запрос поставщику / квота | Запрос по выбранным позициям / зафиксированное предложение поставщика с ценой, количеством, валютой и сроком действия. |
| Финансовый профиль | Версия ставок, валют, округления, формул, условий принятия и вида документа. Для расчёта профиль должен быть опубликован. |
| Расчёт | Предварительный результат можно просмотреть; «Записать версию» сохраняет неизменяемый снимок исходных данных и результата. |
| Позиция исполнения | Принятое клиентом количество. Оно учитывается отдельно от выставленного, оплаченного, распределённого в волну, отправленного и доставленного. |
| Волна | Группа поставок с маршрутом, датами и отдельными событиями по позициям. |

## Первый вход и подготовка

1. Войдите под учётной записью владельца, созданной при развёртывании. После входа доступен **Рабочий стол**; при наличии права аналитики он показывает показатели, иначе — ссылки на разрешённые разделы.
2. Откройте **Настройки → Организация** и добавьте организацию продавца. Заполните название, валюту учёта и реквизиты для документов. Не подставляйте реальные банковские данные в тестовый стенд.
3. В **Настройки → Сотрудники** создайте сотрудников, задав пароль от 12 символов. В **Роли и права** просмотрите разрешённые действия и область доступа. Роль можно дополнить персональным разрешением; персональный запрет отменяет доступ, полученный через роли. Изменения доступа требуют причины.
4. В **Настройки → Правила работы** задайте варианты результатов звонков и причин закрытия заявки без продажи. Именно эти два списка используются в соответствующих формах CRM.
5. В **Настройки → Финансовые профили** создайте профиль: страна ввоза, налоговый режим, валюты, округление, ставки, правила оплаты и вид КП. Начальные ставки `0%` — только заготовка. Подтвердите, что проверили значения, сохраните **черновик**, проверьте контрольный расчёт и затем **опубликуйте** профиль. Дополнительные формулы доступны в раскрывающемся блоке. Создание и публикация требуют прав на финансовые профили и шаблоны.
6. Для обучения создайте отдельные тестовые записи. В новой заявке поставьте отметку **«Тестовая заявка»**: такая заявка исключается из рабочих отчётов. Тестовые платежи, документы и ставки используйте только в отдельной тестовой среде.

Время в интерфейсе отображается по Москве (`UTC+3`). Доступ к записям зависит не только от раздела меню, но и от права на конкретную заявку или клиента. Если операция недоступна, проверьте роль, персональные исключения и область доступа к записи.

## Навигация

| Раздел | Для чего нужен |
|---|---|
| Рабочий стол | Краткая картина работы или ссылки на доступные разделы. |
| Заявки | Поиск, фильтр по этапу, таблица или доска; внутри заявки — все шаги сделки. |
| Клиенты | Клиенты, поставщики, контакты, история звонков, импорт XLSX. |
| База обзвона | Журнал контактов и следующее действие. Из записи «Получен запрос» можно начать заявку. |
| Задачи | Исполнитель, срок, приоритет, состояние и результат. |
| Номенклатура | Товарные варианты и проверка соответствия характеристик. |
| Документы, Оплаты, Согласования | Общие реестры по доступным заявкам; подробные действия выполняются также в карточке заявки. |
| Волны поставок | Маршруты, даты, распределение позиций и события движения. |
| Аналитика | Показатели и выгрузка для сотрудников с соответствующим правом. |
| Обсуждения, Уведомления | Внутренний разговор по работе и системные уведомления. |
| Настройки | Организация, доступ, финансовые профили, рабочие правила, аудит и личный аккаунт в пределах прав. |
| Помощь и процессы | Короткая схема работы внутри самого приложения. |

В верхней строке есть поиск по заявкам, когда сотруднику разрешён их просмотр. Боковое меню показывает только разделы, доступные роли. Некоторые вкладки уже открытой заявки видны всем, кто может открыть заявку, но отдельное действие внутри вкладки всё равно проверяет серверное право.

## Сквозной сценарий: от потребности до поставки

Создавайте учебный сценарий последовательно: следующий шаг обычно опирается на записи предыдущего. Если несколько человек проверяют роли, передавайте друг другу номер заявки.

1. **Клиент и поставщик.** В «Клиентах» добавьте контрагента типа «Клиент» и второго типа «Поставщик», заполните контакты. Историческую клиентскую базу можно загрузить через «Импорт XLSX» после предварительного просмотра.
2. **Контакт и заявка.** В «Базе обзвона» зафиксируйте результат разговора, при необходимости назначьте следующий контакт. Затем создайте заявку через «Заявки → Новая заявка» или из звонка с результатом «Получен запрос». Выберите клиента, организацию продавца и ответственного. Для учебной сделки включите «Тестовая заявка».
3. **Позиции.** В карточке заявки откройте «Позиции запроса», внесите название клиента, CAS, количество и единицу, чистоту и фасовку. Отметьте, допустим ли аналог. Исправления требуют причины и остаются в истории редакций.
4. **Поиск предложения.** В «Номенклатуре» добавьте товарный вариант. Его проверка требует основания по первоисточнику, а не только правильной контрольной цифры CAS. Во вкладке заявки «Запросы поставщикам» выберите поставщика, позиции и срок ответа, скачайте XLSX и после фактической передачи файла нажмите «Отметить отправку».
5. **Квоты.** В «Квотах» зафиксируйте предложение поставщика: товар, закупочную цену, валюту, единицу, доступное количество, минимальный заказ, кратность и срок действия. Для аналога укажите признак аналога. При изменении условий создайте новую редакцию квоты с причиной.
6. **Расчёт.** Во вкладке «Расчёты» выберите опубликованный профиль, квоты и количество. Внесите курс с датой, источником и основанием; при необходимости добавьте общие расходы и способ распределения. Сначала выполните «Предварительный расчёт», проверьте суммы, затем «Записать версию».
7. **КП.** Во вкладке «КП и счета» выпустите КП на записанную версию расчёта, укажите срок действия и условия. Скачайте PDF или XLSX; после передачи клиенту отдельно зафиксируйте канал и время отправки.
8. **Согласие клиента и счёт.** Откройте КП и выберите «Принять состав». Укажите фактически принятое количество и причину; для аналога сохраните решение клиента. Затем выставьте счёт на принятое и ещё не выставленное количество, задав срок и условия оплаты. Неоплаченный счёт можно аннулировать с причиной и выпустить исправленный; история старого счёта сохраняется.
9. **Оплата.** Во вкладке «Оплаты» заявите платёж по документу. Сотрудник с правом подтверждения открывает запись и нажимает «Подтвердить поступление», затем распределяет сумму по подходящим счетам. Только подтверждённое распределение уменьшает долг и учитывается для финансирования. Снятие распределения, возврат или корректировка оформляются «Обратной операцией» с причиной.
10. **Согласование.** Во вкладке «Исполнение» выберите принятые позиции и «Передать на согласование» руководителю. Руководитель в заявке или общем реестре «Согласования» принимает решение: согласовать, вернуть или отклонить. Решение относится к конкретной версии состава.
11. **Волна и движение.** В «Волнах поставок» создайте волну с маршрутом и датами. В позиции исполнения выберите «Распределить в волну» и укажите согласованное количество. Для распределения нужны действующая квота, проверенный товар и достаточное подтверждённое финансирование относительно порога из опубликованного финансового профиля. По мере движения фиксируйте события: заказ, готовность, отправка, прибытие и передача клиенту. Фактические количества отображаются отдельно; перенос возможен только для распределения, по которому ещё нет фактических событий.
12. **Завершение и контроль.** Проверьте актуальные этапы заявки, долг, доставленное количество, историю и связанные задачи. Если сделка закрыта без продажи, выберите причину из настроенного списка. Вложение становится скачиваемым после проверки файла. Сохраните номер заявки для обратной связи по приёмке.

## Пошаговая проверка семи стартовых ролей

Семь стартовых ролей и их права создаёт **явный запуск команды** `python -m app.bootstrap` при первичном создании владельца; обычный запуск CRM сам их не создаёт. Администратор может впоследствии изменить права в UI, поэтому ниже описана **стартовая конфигурация**. Для проверки используйте отдельную учётную запись каждой роли и синтетические данные. Полезно держать две тестовые заявки: принадлежащую менеджеру продаж и чужую, чтобы проверить ограничение «свои/предоставленные».

### Администратор

1. Откройте «Настройки → Сотрудники», создайте тестового сотрудника с одной ролью и откройте его доступ.
2. В «Роли и права» проверьте русские названия действий и область доступа, затем в «Правилах работы» измените тестовый список результатов звонка и сохраните его.
3. Добавьте тестовую организацию продавца, откройте журнал аудита и убедитесь, что изменение записано.
4. Проверьте, что рабочий стол и настройки открываются. Стартовый администратор **не получает автоматически права просмотра заявок или финансовых расчётов**; это ожидаемое разделение функций.

### Руководитель

1. Откройте заявки команды и задачи, при необходимости назначьте ответственного за тестовую заявку.
2. Откройте ожидающее решение согласование через общий реестр или вкладку «Исполнение», выберите «Согласовать» либо «Вернуть на доработку» с комментарием и проверьте статус.
3. Откройте «Аналитику» и «Волны поставок». Стартовая роль даёт обзор и решения по команде; она сама по себе не подтверждает оплату и не настраивает финансовый профиль.

### Владелец расчётов

1. В «Настройках → Финансовые профили» создайте черновик с **учебными**, явно согласованными ставками, сохраните и опубликуйте его только на тестовом стенде.
2. Откройте квоты в тестовой заявке, затем «Расчёты»: заполните курсы и расходы, сравните предварительный итог с ожидаемым и запишите версию.
3. Проверьте, что доступны закупочная цена и подробные финансовые показатели. Эта роль не выпускает КП и счета по умолчанию — следующий шаг передаётся менеджеру продаж.

### Менеджер продаж

1. Откройте клиента или создайте тестового, запишите звонок и задачу на следующий контакт.
2. Создайте **свою** тестовую заявку и позиции, получайте квоты от закупщика; после расчёта выпустите КП, отметьте отправку и зафиксируйте принятое клиентом количество.
3. Выставьте счёт, заявите тестовую оплату и отправьте исполнение на согласование. Подтверждение поступления передайте финансовому контролёру.
4. Попробуйте открыть чужую, не предоставленную вам заявку: она не должна быть доступна. Закупочная цена и подробная прибыль без отдельного права не показываются.

### Закупщик

1. Откройте заявку с потребностью, затем «Номенклатуру»: добавьте и проверьте тестовый товарный вариант с основанием.
2. Создайте запрос поставщику, скачайте XLSX, отметьте отправку после фактической передачи файла.
3. Зарегистрируйте квоту на позицию и товар; проверьте цену, валюту, единицу, доступное количество, срок и редакцию. Если условия изменились, создайте новую редакцию.
4. Стартовая роль видит закупочную цену, но не создаёт финансовый расчёт и не подтверждает клиентскую оплату.

### Логист

1. Откройте согласованную заявку и «Волны поставок», создайте учебную волну с маршрутом, ответственным и плановыми датами.
2. Убедитесь, что квота ещё действует, товар проверен, а подтверждённое финансирование достигает порога профиля расчёта. Распределите согласованное количество из позиции исполнения в открытую волну.
3. Запишите событие готовности, затем отправки, **прибытия** и доставки с фактическим количеством и основанием; проверьте изменение счётчиков.
4. Для проверки переноса создайте **отдельное распределение без событий** и перенесите его плановое количество в другую открытую волну с причиной. Как только по распределению зафиксировано фактическое событие, прямой перенос недоступен; изменение финансового расчёта этой роли не требуется.

### Финансовый контролёр

1. Откройте общий реестр «Оплаты» или вкладку оплаты тестовой заявки. Проверьте, что заявленный платёж пока не уменьшил остаток счёта.
2. Подтвердите поступление и распределите сумму по счёту того же клиента, продавца и валюты. Проверьте остаток и финансирование исполнения.
3. Сделайте на тестовых данных обратную операцию с причиной и проверьте пересчёт остатка, историю и уведомление владельцу затронутой заявки.
4. В этой стартовой роли нет прав на изменение финансовых формул и выпуск коммерческого предложения.

Если кнопка есть, но сервер отказывает, не считайте это успешным действием роли: зафиксируйте экран и текст ошибки. При расширении прав повторите вход и проверку. Доступ «Свои/предоставленные» зависит от владельца заявки и добавленных участников, а не только от названия роли.

## Практические ограничения и безопасная работа

- Финансовые ставки, налоги, курсы и условия оплаты **не поставляются как утверждённые правила компании**. Черновой профиль с нулями не подходит для реального счёта; опубликованный профиль следует сначала сверить на контрольном примере.
- В новых формах настройки ролей, финансового профиля и рабочих справочников используются понятные поля и списки. В нескольких дополнительных полях карточек контрагента, товара, квоты и волны по-прежнему встречается структурированное значение `{}`. Это необязательные расширенные сведения; если их формат не согласован, оставьте значение по умолчанию.
- В CRM есть внутренние обсуждения и прикрепление файлов. Загруженный файл проходит проверку и доступен для скачивания только после успешного результата; класс финансового файла дополнительно ограничивает доступ.
- Массовое копирование данных из другой CRM, автоматическая отправка писем, синхронизация с банком и бухгалтерской системой в текущем интерфейсе не являются частью описанного пути. Отправку и поступление подтверждает сотрудник по фактическому событию.
- При исправлении денег и исполнения используйте предусмотренные обратные операции. Оплаченный счёт или количество в активной волне нельзя просто удалить без предварительного исправления связанной истории.
- Для новых сотрудников объясните различие между статусом, фактом и планом: «заявлено» ≠ «подтверждено», «распределено в волну» ≠ «отправлено», «отправлено» ≠ «доставлено».

Для проверки установки другой командой используйте [сценарий ручной приёмки](manual-acceptance-small-team.md). Для ввода в работу с реальными клиентами отдельно утвердите реквизиты, профиль расчёта, доступы и порядок резервного копирования.

## Как пользоваться комплектом передачи

1. Получающая команда распаковывает архив и следует [инструкции для нового стенда](handover-deployment.md). На компьютере команды создаётся собственный `.env`; данные и пароли текущего стенда в архив не включены.
2. После запуска на чистой базе команда выполняет `python3 scripts/setup_demo_roles.py`. Скрипт создаёт семь отдельных учебных аккаунтов и сохраняет новые случайные пароли в локальном приватном файле `.runtime/demo-role-credentials.txt`.
3. Каждый проверяющий входит под своей ролью и проходит шаги из раздела выше. Для общей сделки участники передают друг другу номер тестовой заявки; действия, которые запрещены роли, проверяются как ограничения доступа.
4. Результаты отмечают в [чек-листе ручной приёмки](manual-acceptance-small-team.md). Для запуска с реальными клиентами учебные аккаунты не создают: владелец заводит рабочие учётные записи и подтверждает финансовые правила своей компании.
