# Подтверждённые поступления сайта

F2 передаёт `request.payment_received` при подтверждении платежа, зарегистрированного на CRM-заявку с источником сайта. `request.payment_refunded` передаёт денежную обратную операцию с `refund.kind`: фактический возврат (`refund`) или исправление подтверждённого поступления (`correction`). Оба вида уменьшают нетто-поступления, но сохраняются раздельно в журнале; перераспределение платежа между счетами (`unallocate`) таким уменьшением не считается. Статус продажи и сумма КП/счёта остаются отдельными фактами.

События содержат стабильные ID платежа/возврата, положительную десятичную сумму, валюту и дату подтверждения/возврата. Они сохраняются в одной транзакции с изменением платежа. Контакты и цены отдельных позиций не передаются. При нескольких обращениях, объединённых в одну CRM-заявку, используется первый источник по `submitted_at, id` для всех её событий.

Порядок выкладки: совместимый приём коротких форм CRM → сайт с миграцией 0012 и приёмом новых событий → CRM с отправкой платежей. На сайте цель «Первое подтверждённое поступление» считает заявки один раз; суммы и возвраты доступны отдельно по валютам в журнале и когортной воронке.

После обновления обеих сторон проверить исторические подтверждённые факты:

```bash
python -m app.integrations.site_payment_backfill
python -m app.integrations.site_payment_backfill --apply
```

Без `--apply` команда только сообщает количества. Повторный запуск не создаёт повторных событий. Вывод не содержит контактов. Если `truncated=true`, увеличить `--limit` (максимум 10000) и проверить полноту. Команда не делает предположений об оплате из статуса «продажа» и не создаёт платежей.
