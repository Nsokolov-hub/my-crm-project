# Стратегия и реестр переноса исторических данных (S17)

## Реестр источников

| Источник (Система/Файл) | Сущности CRM | Внешний ID (External ID) | Владелец колонок | Стратегия обновления | Контрольное число (Сверка) |
|---|---|---|---|---|---|
| Учётная система (1С/SAP) | `Counterparty`, `Seller` | `external_id` (ИНН/KPP/GUID) | Бухгалтерия | Обновление (Upsert) по `external_id`. CRM не перезаписывает реквизиты, пришедшие из системы. | Количество контрагентов. |
| Историческая БД заявок | `Request`, `RequestItem` | `number` (строковый) | Отдел продаж | Только вставка (Insert). Обновление закрытых сделок запрещено. | Кол-во заявок, суммы. |
| Старые расчёты (Excel/Старая CRM) | `Calculation`, `CommercialDocument` | `number` (счёта/КП) | Коммерческий отдел | Архивирование. Старые расчеты получают `snapshot["is_legacy_archive"] = True` без пересчета. | Баланс дебиторской задолженности по валютам. |
| Выписки банка | `Payment` | `external_id` (УИН платежа) | Бухгалтерия | Только вставка. Если дубликат по `external_id` — игнор. | Обороты за месяц по валютам. |

## Регламент переключения (Freeze/Delta)

1. **Dry-Run (Пробный прогон):**
   Из старой системы выгружаются данные (JSON/CSV). Запускается `scripts/migrate_legacy.py` с флагом `--dry-run`. 
   Убеждаемся, что нет ошибок внешних ключей и контрольные суммы (балансы) сходятся.

2. **Freeze (Заморозка):**
   Остановка создания новых заявок в старой системе (обычно пятница вечер). Выгрузка полного слепка данных.

3. **Delta (Финальный перенос):**
   Запуск `scripts/migrate_legacy.py --commit`. Сверка отчета о миграции с реестром.

4. **Ограничения:**
   Старые расчёты вносятся в базу в виде `is_legacy_archive=True`. CRM их не пересчитывает новыми шаблонами (CalculationProfiles). 
   Любое изменение старой заявки потребует создания нового расчёта по новым правилам, что полностью соответствует требованиям неизменности истории.
