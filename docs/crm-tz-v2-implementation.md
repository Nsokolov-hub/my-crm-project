# Доработки CRM по ТЗ v2.0

## Основной маршрут

Контрагент → заявка со структурированными позициями → RFQ XLSX → табличная квота → выбор строк → серверный предварительный расчёт → неизменяемая версия → коммерческое предложение → исполнение.

Квоты и позиции расчёта хранят поставщика, номенклатуру, фасовку, валюту и исходную строку заявки. Цена из истории подставляется только при совпадении поставщика, номенклатуры, фасовки и валюты и действует 21 день. Старые квоты остаются неизменными.

Расчётная методика `itemized_v2` работает в RUB с прямыми курсами каждой закупочной валюты, правилами таможни по товарным группам, расходами, распределением по количеству, построчной наценкой, условиями оплаты, финансированием и закрытой внутренней корректировкой. Предпросмотр не записывает результат. Сохранение создаёт новую строку `Calculation` с полным snapshot, хешем, номером версии и ссылкой на предыдущую версию. Существующий PostgreSQL-триггер защищает `calculations` от изменений; новая миграция добавляет такую же защиту для табличных квот.

Для повседневной работы добавлены импорт XLSX с предпросмотром и разбором дублей по ИНН, поисковые справочники с быстрым созданием, справочник видов расходов, английские заголовки RFQ, номер заявки в имени файла, описание обсуждения и счётчик непрочитанных сообщений.

## Включение

1. Применить `alembic upgrade head` на PostgreSQL после обычного резервного копирования базы.
2. В «Настройки → Финансовые профили» создать виды расходов и профиль расчёта `itemized_v2`.
3. Выбрать страну ввоза, проверить таможенные правила и диапазоны сборов, задать финансовую ставку и начальные расходы. Опубликовать профиль после контрольного расчёта.
4. В заявке создать структурированные позиции с фасовками, занести табличную квоту и выбрать её строки для расчёта.

Исходный профиль содержит только значения, прямо названные в ТЗ: 5% для реагентов и стандартных образцов, 73 800 ₽ для группы колонок, 4 997 ₽ при базе до 500 000 ₽ и НДС 22%. Для суммы свыше 500 000 ₽ расчёт потребует настроить подходящий диапазон. Для лабораторной посуды стартовое правило `NONE` служит редактируемым заполнителем и должно быть подтверждено до применения.

## Решения, ожидающие заказчика

- Точная таблица таможенных сборов после 500 000 ₽ и правило для лабораторной посуды.
- Момент начала отсрочки, финансовая ставка и налоговый режим для организации.
- Особые правила внутреннего бонуса и клиентских документов.

Пока значения не согласованы, их следует настроить в профиле; недостающий диапазон приводит к понятной ошибке предпросмотра.

## Технические границы

- Действующая схема проекта использует неизменяемые строки `Calculation` как версии. Таможенные правила, диапазоны и начальные расходы принадлежат snapshot профиля; отдельные таблицы `CalculationVersion`, `CustomsRule`, `CustomsFeeBracket` и `CalculationProfileExpense` в этой итерации не вводились.
- Одна квота и один расчёт содержат до 100 строк. Поиск номенклатуры и контрагентов идёт через API; выбор позиций заявки в табличной квоте поддерживает серверный поиск.
- Сборка frontend, статический анализ Python и импорт приложения проверены. Миграция не запускалась на PostgreSQL в рабочем окружении этой задачи: локальный Docker daemon недоступен, а прежние миграции используют PostgreSQL-триггеры и не выполняются на SQLite.
