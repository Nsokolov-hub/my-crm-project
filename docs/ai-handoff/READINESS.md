# Оценка готовности CRM на 19.09.2026

## Итог

**Около 40% готовности основного объёма П1 к сдаче пользователю.** Разумный диапазон неопределённости — 30–50%. В коде уже присутствует значительная часть функций, однако полноценная работа всех ролей, сквозного процесса и эксплуатации ещё не доказана.

Это не точное измерение объёма оставшегося труда. Оставшиеся 60% могут занять больше времени, чем написание имеющегося кода: здесь много интеграции, финансовых крайних случаев, защиты данных и восстановления.

## Как получена оценка

| Направление | Вес в оценке | Текущая оценка | Обоснование |
|---|---:|---:|---|
| Бизнес-функции П1 | 35% | 60% | Реализованы основные сущности и операции; остаются ошибки финансовых остатков, исправления принятого состава, неполная аналитика и настройки |
| Пользовательские сценарии и интерфейс | 20% | 50% | Интерфейс собирается, базовый сценарий проверен; есть несовпадения API, отсутствующие формы/переходы и непроверенный полный цикл |
| Доступ, целостность и история | 15% | 20% | Есть RBAC, сессии, CSRF, MFA, журнал и транзакции; выявлены критичные пропуски в финансовых областях доступа и повторе команд, новая защита истории не проверена |
| Доказательство соответствия ТЗ | 20% | 25% | 33 локальных теста проходят; отсутствует полная приёмка A01–A22, browser E2E и актуальный набор PostgreSQL-доказательств |
| Развёртывание и эксплуатация | 10% | 10% | Есть заготовки контейнеров и lock-файлы; нет законченного восстановления, CI, нагрузки и подтверждённого чистого развёртывания |

Взвешенный результат: 0,35×60 + 0,20×50 + 0,15×20 + 0,20×25 + 0,10×10 = **40%**. Все промежуточные проценты — экспертные оценки, а веса отражают важность направлений для сдачи CRM. Они не являются статистикой покрытия.

П2 и П3 в эти 40% не включены: бухгалтерская сверка, внешние интеграции и аналитический ИИ-помощник выделены самим ТЗ в последующие очереди. Эти функции сейчас не реализованы. Для их оценки нужны отдельные границы интеграций; смешивать их с процентом П1 некорректно.

## Что фактически есть

- Сервер на FastAPI с модулями `core`, `crm`, `commerce`, `communication`, `analytics`.
- Пользователи, роли и разрешения; сессии, CSRF, MFA и журнал аудита.
- Контрагенты, контакты, обзвон, задачи, заявки и версии позиций.
- Каталог химической продукции, CAS, запросы поставщикам и версии квот.
- Десятичный расчёт, формулы в ограниченном интерпретаторе, сохранённые снимки.
- КП/счета, файлы PDF/XLSX, принятие состава, платежи, распределения и обратные операции.
- Согласования, волны и количественные события исполнения.
- Чаты, уведомления, приватное хранение файлов и очередь антивирусной проверки.
- Импорт XLSX с предварительным просмотром, разрешением конфликтов и фоновой записью.
- Русскоязычный интерфейс, настройки, базовая аналитика, Docker-конфигурация, миграции.

Перечень означает наличие реализации, а не полное соответствие каждого модуля ТЗ.

## Проверки с доказательствами

Свежий запуск 19.09.2026:

```text
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=backend .venv/bin/pytest backend/tests -m 'not postgres' -q -p no:cacheprovider
33 passed, 6 deselected, 2 warnings in 3.13s

pnpm --dir frontend build
TypeScript: успешно; Vite: успешно, 1875 модулей
```

Два предупреждения Python связаны с устареванием API зависимостей. При сборке интерфейса есть два предупреждения об аннотациях PURE в Zod. Они не остановили проверки.

Ранее вручную были проверены вход, клиент, тестовая заявка и позиция с сохранением в PostgreSQL. Ранее также прошли шесть настоящих конкурентных PostgreSQL-тестов. После добавления миграции `51eab019a784_protect_history` и изменения тестовой подготовки этот PostgreSQL-набор повторно не проверен. Его старый результат нельзя приписывать текущему состоянию миграций.

При передаче 15.09.2026 Ruff сообщал три замечания в PostgreSQL-тесте, Stylelint — один повторный селектор. ESLint проходил. Эти замечания не исправлялись в рамках подготовки плана. Файлов frontend-тестов не обнаружено: присутствует только `frontend/src/test/setup.ts`.

## Существенные проблемы, обнаруженные аудитом кода

Пункты ниже проверены чтением конкретных путей кода. Для них ещё нужно записать воспроизводящие тесты; отсутствие runtime-прогона отдельно оговорено.

| Приоритет | Проблема | Где искать | Требуемое доказательство исправления |
|---|---|---|---|
| Критичный | Закупочные финансовые права проверяются через наличие разрешения без области конкретной заявки | `commerce/procurement.py`, `core/security.py` | `requests.read=all` и `finance.purchase.read=own` не раскрывают закупку чужой заявки |
| Критичный | Повтор команды может вернуть старый полный JSON после отзыва права на закрытые поля | `core/service.py:idem`, `commerce/financial.py` | После отзыва права повтор старого ключа не отдаёт закрытый snapshot и не создаёт вторую операцию |
| Критичный | Платёж может показать распределения по счетам из других, недоступных заявок | `commerce/payments.py:payment_view` | Доступ к исходной заявке не открывает чужие счета/ссылки/суммы |
| Критичный | Округление частичных сумм способно дать отрицательный последний остаток | `commerce/documents.py:partial_amount` | Для net=0.02, quantity=4, четырёх частей по 1 нет отрицательных частей; сумма частей точно 0.02 |
| Высокий | Явный null в PATCH обходит некоторые ограничения; seller_id=null обходит условие проверки смены продавца | `crm/schemas.py`, `crm/routes.py:edit_request` | Обязательные поля не обнуляются; продавец документа защищён и для null |
| Высокий | Изменение потребности не проверяет уже принятое количество и смену единиц | `crm/routes.py:edit_item` | Нельзя уменьшить потребность ниже принятого объёма или сменить единицу с нарушением пересчёта |
| Высокий | Нет законченного процесса исправления/отмены принятого состава и нового согласования | `commerce/documents.py`, `commerce/fulfillment.py` | Полный A16: возврат → изменение состава → новое согласование → старое решение неприменимо |
| Высокий | Профили и финансовые поля не имеют полного раздельного ограничения доступа | `commerce/financial.py`, `communication/access.py` | Каждое финансовое разрешение и его scope проверяются отдельно; параметры вознаграждения не раскрываются через профиль |
| Высокий | Отчёты и детализация не совпадают по фильтрам и контрактам, задачи доступны разными путями неодинаково | `analytics/routes.py`, `crm/routes.py`, `frontend/src/pages/Dashboard.tsx` | A19 и негативные проверки доступа через dashboard/next_task |
| Высокий | UI файлов использует неподдерживаемую классификацию, непрочитанные и сроки имеют несовпадения | `pages/Communication.tsx`, `app/Layout.tsx`, формы дат | Реальная загрузка закрытого файла; корректный счётчик; сохранение срока без изменения времени |
| Высокий | Backup/restore-оболочки ссылаются на отсутствующий обработчик | `scripts/backup.sh`, `scripts/restore.sh` | Полное восстановление БД и файлов в отдельную среду |

Дополнительный контейнерный риск: PDF-генератор ищет системный Unicode-шрифт, а Dockerfile не устанавливает его явно. Это требует проверки в контейнере; отказ контейнерной генерации в этом аудите не воспроизводился.

## Что означает завершение проекта

П1 становится готовым после выполнения обязательных F/N-требований, прохождения A01–A22 на актуальном коде, отсутствия блокирующих дефектов и передачи эксплуатационных инструкций. Рабочий экран, зелёная сборка или отдельный тест не заменяют эти условия.

На текущем этапе проект пригоден для продолжения разработки и контролируемого тестирования. Использовать его как принятую рабочую CRM с важными данными пока рано.
