# Изменения по замечаниям бизнеса от 2 октября 2026

## Контрагенты, контакты и документы

Контакты теперь можно создавать для поставщиков, покупателей и компаний с обоими типами. В форме контакта выбирается действующий контрагент рабочей базы. В его карточке остаётся список со ссылками на полные карточки контактов. Доступ к контактам соответствует доступу к компании.

Ответственный отображается в списке контрагентов и в карточке компании. Сотрудник с правом переназначения может выбрать другого действующего сотрудника при создании или редактировании компании; при переназначении указывается причина.

В карточке появился раздел **«Документы контрагента»**. В него загружаются учредительные документы, договоры и прочие файлы. Список показывает категорию, дату и результат проверки. Скачивание становится доступно после успешной проверки файла. Документ можно убрать в архив, сохранив сам файл и историю действий. Загрузка, скачивание и архивирование учитывают права сотрудника и доступ к компании.

## Короткие номера заявок

Новые заявки получают последовательные номера: `1` … `1000`, затем `A1` … `A1000`, `B1` … `B1000` и далее. После `Z1000` идёт `AA1`. Используются английские буквы. Номер не сбрасывается ежегодно и не используется повторно после удаления заявки; параллельное создание заявок защищено от совпадений.

Старые номера сохраняются. При обновлении счётчик учитывает существующие заявки, включая архивные, и уже занятые короткие номера. Поэтому первая новая заявка в действующей базе продолжает последовательность, а не обязательно получает номер `1`.

## Один запрос для всех поставщиков

В форме создания запроса поставщик стал необязательным. Можно выбрать позиции, сформировать **общий запрос**, скачать один XLSX и отправить его нескольким поставщикам. Их квоты могут ссылаться на этот общий запрос. При необходимости остаётся возможность сформировать отдельный запрос конкретному поставщику.

Все исходные столбцы и значения заявки сохраняются. Для XLSX, загруженных после обновления, выгрузка также переносит оформление выбранных строк: границы, шрифты, заливку, выравнивание, ширину столбцов и высоту строк. При объединении таблиц столбцы с одинаковыми заголовками не дублируются. Для текстовых таблиц и старых импортов без сохранённой привязки к оформлению создаётся читаемая таблица с границами и переносом текста. Формулы при импорте нужно заменить значениями.

## Недели и расходы волн

Планирование волны задаётся **номером ISO-недели и годом** для закрытия, отправления и прибытия. Например, неделя `35` соответствующего года. Система проверяет существование недели и порядок этапов. Для существующих волн недели определяются из ранее введённых дат, которые сохраняются.

До добавления товаров бюджет волны показывает предварительные расходы и минимальный настроенный таможенный сбор для нулевой таможенной стоимости. После сохранения расчётов следующих заказов расходы и таможенный сбор заново распределяются по всему составу волны. Учитываются последние планы заказов и принятые позиции, уже распределённые в волну, без повторного учёта одной позиции.

Размер таможенного сбора выбирается по суммарной таможенной стоимости волны. Он прибавляется к общим расходам и распределяется по количеству товаров; показывается также сбор на единицу. В интерфейсе название **«Таможенная база»** заменено на **«Таможенная стоимость»**. Если для исторических позиций не хватает базы распределения, система сообщает об этом, а не рассчитывает неизвестную стоимость как нулевую.

## НДС, срок поставки и история расчётов

В начале нового расчёта доступен переключатель **«Расчёт с вычетом НДС»**. Без вычета ввозной НДС входит в себестоимость и цену. С вычетом он из них исключается; сумма ввозного НДС продолжает отображаться отдельно. Денежная потребность (`cash_need`) включает его в обоих режимах, поскольку налог нужно оплатить при ввозе. Эти правила применяются к методике расчёта по табличным квотам; старые профили с пользовательскими формулами сохраняют свою методику.

Поле **«Общий срок поставки, дней»** позволяет указать срок для покупателя. Он переносится в новые КП и связанные счета. Если срок не задан для расчёта по табличной квоте, используется максимальный срок выбранных позиций.

Изменение состава волны, общих расходов или курса общей валютной статьи отмечает сохранённые расчёты как требующие пересчёта. Для актуального КП создайте новую версию расчёта. Если бюджет изменился между предварительным расчётом и сохранением, система просит повторить проверку.

Сохранённые версии расчётов и выпущенные КП или счета остаются историческими снимками: их суммы, реквизиты, сроки и файлы не переписываются при пересчёте волны. Новый расчёт и новый документ оформляются отдельными версиями.

## Оплаты, запуск работы и группы квот

В форме **«Заявить оплату»** валюта выбирается из выпадающего списка действующих валют. При выборе счёта подставляется его валюта; система проверяет соответствие валюты платежа счёту. API также нормализует `Rub` и `rub` в `RUB`.

Передача позиций в работу остаётся отдельным действием: в списке позиций отметьте нужные строки и нажмите **«В работу»**. Платёж вносится независимо от этого действия. Согласование закупки и оформление заказа могут проходить до оплаты; действующие требования к финансированию отгрузки сохраняются.

В ранее обновлённом шаблоне квот остаётся последний столбец **«Товарная группа»** с выпадающим списком и отдельным листом справочника. Для новой номенклатуры можно указать название или код действующей группы. Пустое значение или `0` использует группу исходной позиции, а при её отсутствии — группу «Прочее». Найденный по артикулу товар сохраняет свою текущую группу. Проверка показывает фактическую группу до записи; неизвестная группа блокирует импорт. Поставщики из файла квот не создаются.

## Обновление сервера

Перед обновлением сделайте резервную копию базы и файлов по [инструкции установки](install-hosting-vps.md). Сохраните рабочие `.env`, `COMPOSE_PROJECT_NAME` и Docker volumes. Обновите исходники и пересоберите сервер и интерфейс: новые элементы формы требуют обновления обеих частей приложения.

Для Docker-установки после обновления исходников:

```bash
docker compose build api web
docker compose stop api worker web
docker compose run --rm migrate
docker compose up -d --no-build
docker compose ps -a
```

Сервис `migrate` выполняет `alembic upgrade head`; новая миграция — `b5131002`. Она создаёт хранилище документов и счётчик заявок, добавляет привязку к оформлению исходной таблицы и номера недель, разрешает общий запрос без поставщика. Продолжайте запуск приложения после успешного завершения миграции. Проверьте доступность API, интерфейса и worker.

Для установки без Docker выполните миграцию из окружения приложения с рабочими настройками подключения к базе, затем пересоберите интерфейс и перезапустите сервер и worker:

```bash
PYTHONPATH=backend alembic -c backend/alembic.ini upgrade head
```

После обновления откройте карточку контрагента, форму контакта и форму оплаты; скачайте новый шаблон квот, проверьте общий запрос XLSX и расчёт заполненной волны. Старые заявки, расчёты и документы должны оставаться доступными.
