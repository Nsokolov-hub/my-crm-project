# Установка CRM на своём компьютере через Docker

Эта инструкция помогает запустить «Реактив CRM» на **одном компьютере** для знакомства, ручной приёмки или работы без доступа извне. После установки CRM открывается в браузере по адресу <http://127.0.0.1:8080/>. Если сотрудники должны заходить из интернета, используйте [инструкцию для сервера](install-hosting-vps.md).

Архив проекта содержит программу, но не содержит базу вашей компании, загруженные файлы, пароли и настроенный `.env`. Эти данные создаются на компьютере при первом запуске.

## 1. Что подготовить

1. **Docker с Compose.** На Windows и macOS установите [Docker Desktop для Windows](https://docs.docker.com/desktop/setup/install/windows-install/) или [Docker Desktop для Mac](https://docs.docker.com/desktop/setup/install/mac-install/) и запустите его. На Windows используйте режим Linux-контейнеров с WSL 2; [порядок включения WSL 2](https://docs.docker.com/desktop/features/wsl/) описан у Docker. На Linux установите [Docker Engine](https://docs.docker.com/engine/install/) и [плагин Compose](https://docs.docker.com/compose/install/linux/). Далее команды `docker` должны работать от вашей учётной записи.
2. **Python 3** нужен только для подготовительных скриптов на компьютере. Python внутри контейнеров устанавливать отдельно не требуется.
3. Для первой загрузки образов и сборки приложения нужен интернет. Рекомендуются не менее **4 ГБ оперативной памяти** и **10 ГБ свободного места**. Антивирус ClamAV при первом запуске может запускаться несколько минут; на Mac с Apple Silicon его AMD64-образ может запускаться дольше.
4. Убедитесь, что порты `8080`, `8000`, `54329` и `3310` на этом компьютере свободны. По умолчанию они доступны только с самого компьютера (`127.0.0.1`).

Откройте Terminal (macOS/Linux) или PowerShell (Windows) и проверьте установку:

```text
docker version
docker compose version
```

Если `docker version` не показывает работающий сервер Docker, запустите Docker Desktop либо службу Docker и повторите проверку. На macOS/Linux проверьте Python командой `python3 --version`; в PowerShell — `py -3 --version`.

## 2. Получить проект и открыть его папку

**Если вы получили ZIP:** распакуйте его в постоянную папку, например `Documents/reaktiv-crm`. Откройте терминал **в папке, где лежат `docker-compose.yml`, `README.md` и каталог `scripts`**. На macOS/Linux для перехода используйте `cd /путь/к/reaktiv-crm`, в PowerShell — `cd 'C:\путь\к\reaktiv-crm'`. В дальнейшем все команды выполняйте именно здесь.

**Если работаете через Git:** вместо распаковки клонируйте репозиторий и перейдите в него:

```text
git clone https://github.com/Nsokolov-hub/my-crm-project.git
cd my-crm-project
```

Если на компьютере уже есть другая установка этого проекта, не запускайте вторую копию с тем же `COMPOSE_PROJECT_NAME`: они будут использовать одни Docker-тома. Для отдельного тестового стенда задайте другое имя проекта в новом `.env` **до первого запуска** и при необходимости измените порты.

## 3. Создать приватные настройки

На macOS/Linux выполните:

```bash
python3 scripts/init-env.py
```

На Windows в PowerShell выполните:

```powershell
py -3 scripts/init-env.py
```

Скрипт создаст `.env` со случайными паролями базы и секретным ключом. Он не печатает их в терминал и **не перезаписывает существующий `.env`**. Если файл уже существует, остановитесь и используйте настройки имеющейся установки; повторно создавать их поверх рабочей базы нельзя. Не отправляйте `.env` по почте, не прикладывайте к отчётам и не добавляйте в Git.

Обычно менять файл не нужно. Если порт `8080` занят, откройте `.env` в текстовом редакторе, добавьте `CRM_HTTP_PORT=8081` и добавьте к `ALLOWED_ORIGINS` адрес `http://127.0.0.1:8081` (через запятую, без пробела). После этого открывайте CRM на порту `8081`. Аналогично можно задать `CRM_API_PORT`, `CRM_DB_PORT` и `CRM_CLAMAV_PORT`. После изменения `.env` у **уже запущенной** установки пересоздайте API-контейнер командой `docker compose up -d --no-build --force-recreate api`.

## 4. Собрать и запустить CRM

Команды одинаковы для Terminal и PowerShell:

```text
docker compose build api web
docker compose up -d --no-build
docker compose ps -a
```

Первая команда собирает сервер и интерфейс; вторая загружает необходимые Docker-образы, создаёт базу и запускает сервисы. Подождите, пока `db`, `clamav`, `api` и `web` станут `healthy`, `worker` будет запущен, а `migrate` завершится с кодом `0`. Отдельное завершение `migrate` — нормальный результат: он выполняет подготовку базы. Во время первого запуска ClamAV ожидание может занять несколько минут. Повторяйте `docker compose ps -a`, пока состояния не установятся.

Проверка в браузере:

- <http://127.0.0.1:8080/> — страница входа CRM (или ваш порт из `.env`);
- <http://127.0.0.1:8080/ready> — ответ о готовности сервера.

Если страница не открывается, сначала посмотрите состояния `docker compose ps -a`, затем журналы проблемного сервиса, например `docker compose logs --tail=100 api` или `docker compose logs --tail=100 web`. Не публикуйте журналы, пока не убедитесь, что они не содержат конфиденциальных данных.

## 5. Создать учётные записи: выберите один вариант

### Вариант А — база для работы компании

Создайте первого владельца. Подставьте **свою** почту вместо примера; команда скрыто запросит пароль длиной не менее 12 символов:

```text
docker compose exec api python -m app.bootstrap --email owner@company.example --name 'Владелец' --all-roles
```

Войдите на <http://127.0.0.1:8080/>. Флаг `--all-roles` нужен первому владельцу для начальной настройки. В **Настройках → Роли и права** проверьте доступы, затем в **Настройках → Сотрудники** создайте обычные учётные записи с нужной ролью каждому сотруднику. Не используйте общий пароль на всех.

Перед выпуском реальных коммерческих документов добавьте организацию продавца и реквизиты, нужные справочники и финансовый профиль. Ставки, формулы, условия и округление задайте по правилам вашей компании и проверьте контрольный расчёт. Порядок работы описан в [руководстве пользователя](user-handbook.md).

### Вариант Б — чистый демонстрационный стенд для проверки семи ролей

**Только если база новая и в ней ещё нет сотрудников**, вместо владельца из варианта А создайте семь учебных учёток. Не запускайте этот скрипт на рабочей базе компании.

macOS/Linux:

```bash
python3 scripts/setup_demo_roles.py
```

Windows PowerShell:

```powershell
py -3 scripts/setup_demo_roles.py
```

Скрипт создаст по одной учётной записи для Администратора, Руководителя, Владельца расчётов, Менеджера продаж, Закупщика, Логиста и Финансового контролёра. Логины и случайные пароли будут **только на вашем компьютере** в `.runtime/demo-role-credentials.txt`; в терминал пароли не печатаются. На Windows дополнительно проверьте, что папка проекта доступна только тем, кому нужны эти данные. После входа под одной ролью выйдите из CRM перед входом под следующей.

Скрипт рассчитан на однократный запуск: он откажется менять существующие пароли или дополнять базу с пользователями. Для проверки используйте [ручной тест-план](manual-functional-test-plan.md). Если меняли веб-порт, передайте правильный адрес в команду, например `python3 scripts/setup_demo_roles.py --url http://127.0.0.1:8081/` (на Windows используйте `py -3`).

## 6. Убедиться, что данные сохраняются

После входа под владельцем или Администратором добавьте тестовую организацию в **Настройках → Организация**, нажмите **Сохранить** и обновите страницу. Организация должна остаться в списке. Создайте тестового сотрудника, обновите страницу и проверьте его наличие. Затем войдите под ним в отдельном приватном окне и проверьте доступные разделы.

Если форма открывается, но запись не появляется, проверьте в инструментах браузера **Network → Fetch/XHR** запрос после нажатия **Сохранить**: для организации ожидается `POST /api/v1/sellers`, для сотрудника — `POST /api/v1/admin/users`, успешный ответ — `201`. Если запроса нет, убедитесь, что запущен свежесобранный `web`, затем обновите страницу с очисткой кэша. Если сервер вернул `403 ORIGIN_FORBIDDEN`, добавьте **точный адрес открытой страницы** (протокол, имя/IP и порт) в `ALLOWED_ORIGINS` файла `.env` и пересоздайте `api`:

```text
docker compose up -d --no-build --force-recreate api
```

Если ответ `403 CSRF_INVALID`, обновите страницу и войдите снова. Причину другого ответа ищите в сообщении формы и в `docker compose logs --tail=100 api`.

## 7. Повседневные команды

Все команды выполняются из папки проекта:

| Задача | Команда |
| --- | --- |
| Посмотреть состояние | `docker compose ps -a` |
| Посмотреть недавние ошибки | `docker compose logs --tail=100 api` |
| Остановить без потери данных | `docker compose stop` |
| Запустить снова | `docker compose up -d` |
| Удалить контейнеры, **сохранив** данные | `docker compose down` |

База, файлы и антивирусные данные хранятся в Docker-томах. **Не выполняйте `docker compose down -v`** для обычной остановки: `-v` удаляет тома вместе с базой и файлами CRM. При переносе на другой компьютер одного ZIP с исходниками недостаточно — нужны резервная копия данных и `.env` этой установки.

## 8. Резервная копия и обновление

Перед первым рабочим использованием проверьте, что резервная копия создаётся. На macOS/Linux:

```bash
python3 scripts/recovery.py backup --mode docker --compose-storage --retention 7
```

На Windows PowerShell:

```powershell
py -3 scripts/recovery.py backup --mode docker --compose-storage --retention 7
```

Скрипт создаст архив в папке `backups/`, включив базу и загруженные файлы, и выведет путь с контрольной суммой. База и файлы копируются последовательно, поэтому рабочую копию делайте в тихое окно без изменений в CRM. Храните актуальную копию **вне этого компьютера** с доступом только для ответственных лиц. Команда восстановления перезаписывает существующие данные; выполняйте её только по [инструкции восстановления](deployment.md) после выбора нужного архива.

Если проект получен через Git, перед обновлением сделайте резервную копию, затем выполните:

```text
git pull origin main
docker compose build api web
docker compose up -d --no-build
docker compose ps -a
```

Если проект передан ZIP-архивом, сохраните текущую папку и резервную копию, распакуйте новую версию в отдельную папку, перенесите туда **свой** `.env` (не подменяйте его шаблоном), остановите старый стек командой `docker compose down` **без `-v`**, затем соберите и запустите новый стек из новой папки. Если это учебный стенд, отдельно сохраните `.runtime/demo-role-credentials.txt` в приватном месте: при смене папки файл доступов не переносится автоматически, а повторный запуск демо-скрипта запрещён. Проверьте, что `COMPOSE_PROJECT_NAME` в `.env` остался прежним: так новая версия подключится к тем же Docker-томам. После обновления повторите проверку входа, организации и сотрудника из раздела 6.

## 9. Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| `docker` не находится или не подключается к серверу | Установлен и запущен Docker Desktop/Engine; команда `docker version` работает. |
| Порт уже занят | Измените соответствующий `CRM_*_PORT` в `.env`; для веб-порта измените и `ALLOWED_ORIGINS`, затем пересоздайте API. |
| `clamav` долго не становится `healthy` | Дайте несколько минут на первый запуск, проверьте доступ к интернету, свободную память и `docker compose logs --tail=100 clamav`. |
| `migrate` завершился с ошибкой | Посмотрите `docker compose logs --tail=100 migrate` и состояние `db`; не удаляйте том базы ради повторной попытки. |
| Скрипт сообщает, что `.env` уже существует | Это защита ваших паролей и данных. Используйте существующий файл; для второй независимой установки нужна отдельная папка и имя Compose-проекта. |
| Демо-скрипт отказывает | Он работает только один раз на новой базе без пользователей. Для рабочей базы создавайте сотрудников через интерфейс. |
| После обновления виден старый интерфейс | Повторите `docker compose build api web` и `docker compose up -d --no-build`, затем перезагрузите страницу браузера с очисткой кэша. |

Исходные команды и состав контейнеров можно сверить в `docker-compose.yml`, `scripts/init-env.py` и [технической инструкции](deployment.md). Для запуска на сервере с доступом сотрудников из интернета используйте [инструкцию для хостинга](install-hosting-vps.md).
