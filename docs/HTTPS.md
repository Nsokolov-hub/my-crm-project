# Домен и HTTPS

Конфигурация подготовлена для существующей Docker Compose установки. На рабочем сервере в рамках этой разработки ничего не изменялось.

1. Купите домен или используйте поддомен имеющегося, например `crm.example.ru`.
2. В DNS создайте A-запись `crm` → `45.15.252.12`, если это по-прежнему IP вашего VPS. Для корневого домена вместо `crm` укажите `@`. Если IPv6 не настроен, AAAA-запись не добавляйте. Проверьте результат командой `dig +short crm.example.ru`.
3. Откройте TCP 80 и 443 в сетевом экране VPS; UDP 443 нужен для HTTP/3. Сохраните доступ по SSH. Порты базы и API оставьте доступными только локально. В базовом compose веб-порт 8080 также привязан к 127.0.0.1; удалите прежний внешний override 8080, если его добавляли на сервере.
4. В существующем `.env` заполните:

```dotenv
CRM_DOMAIN=crm.example.ru
TLS_EMAIL=admin@example.ru
ENVIRONMENT=production
ALLOWED_ORIGINS=https://crm.example.ru
```

Сохраните действующие пароли базы. Для `SECRET_KEY` требуется самостоятельный случайный секрет длиной от 32 символов; production также включает обязательную MFA. Не заменяйте рабочий `.env` целиком примером из репозитория. Имя домена задаётся без `https://` и пути.

5. После резервной копии и обновления приложения запустите из каталога проекта:

```bash
docker compose -f docker-compose.yml -f docker-compose.https.yml config --quiet
docker compose -f docker-compose.yml -f docker-compose.https.yml up -d --build
docker compose -f docker-compose.yml -f docker-compose.https.yml logs --tail=100 caddy
curl -I https://crm.example.ru
```

Должна открываться CRM с действительным сертификатом, а `http://crm.example.ru` — перенаправляться на HTTPS. Если на 80/443 уже работает другой nginx, сначала выберите один внешний прокси и освободите эти порты для Caddy; не останавливайте неизвестные сервисы без проверки.

Caddy получает и обновляет сертификаты автоматически при корректных DNS и доступных портах. Сертификаты сохраняются в томах `caddy-data` и `caddy-config`; не удаляйте их при обновлении. Подробнее: [официальная документация Caddy](https://caddyserver.com/docs/automatic-https).

Без домена продолжайте использовать существующую конфигурацию; файл HTTPS подключается только после настройки DNS. Не включайте production для доступа по обычному HTTP: защищённая сессионная cookie требует HTTPS.
