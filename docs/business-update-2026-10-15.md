# Правки бизнеса от 15 октября 2026

## Счёт как КП

Печатная форма счёта (PDF и XLSX) теперь сделана по образцу КП: тот же заголовок с логотипом и номером, блоки «Плательщик» и «Поставщик», таблица позиций с ценой и суммой с НДС, итог «К оплате с НДС» и «В том числе НДС».

- Строка «Заявка: …» из счёта убрана.
- Подпись такая же, как в КП: «Генеральный директор» слева, «Гильмутдинов Т.Ф» справа. Поля «Подписант» и «Должность подписанта» в карточке продавца на счёт больше не влияют.
- Реквизиты для оплаты (банк, БИК, счета, ИНН, КПП, получатель) идут отдельным блоком под сторонами.
- Уже выпущенные счета не меняются: их файлы сохранены в момент выпуска.

## Аналитика: каталог отчётов

Раздел «Аналитика» открывается списком отчётов. Нажатие на отчёт открывает его отдельную страницу (`/analytics/<отчёт>`) с настройками:

- **Период:** «Этот месяц», «Прошлый месяц», «Этот квартал», «С начала года» или свой период по датам. Именованный период пересчитывается от сегодняшней даты.
- **Показывать графики** — для отчётов с графиком (продажи по менеджерам, заявки по этапам, взаиморасчёты, активность сотрудников).
- Браузер запоминает настройки каждого отчёта.

Отчёты: «Продажи по менеджерам», «Заявки и конверсия» (с экспортом XLSX), «Производители и бренды», «Ответы поставщиков», «Взаиморасчёты по валютам», «Активность сотрудников».

**Права.** Новое право «Все отчёты аналитики» (`analytics.reports`). Без него сотрудник видит только «Продажи по менеджерам» — и только по своим заявкам, если его права ограничены своими. Миграция `b5131016` выдаёт новое право всем ролям и сотрудникам с правом «Аналитика», кроме стандартной роли «Менеджер продаж». Рабочий стол с показателями по-прежнему открывается правом «Аналитика».

## Расчёт

- **Количество — 1 шт.** Количество в расчёте по умолчанию 1 шт. для каждой позиции, оно больше не берётся из заявки. Нужное количество можно ввести в строке.
- **Общий срок поставки — только вручную.** Поле больше не подставляет самый долгий срок квот. Рядом показана подсказка с этим сроком, но записать расчёт без срока нельзя: «Проверьте и укажите общий срок поставки». Предварительный расчёт без срока работает.
- **Плановый объём делит расходы.** Расчёт по плановой волне делит общие расходы волны и таможенный сбор на плановый объём. Раньше количество в расчёте бралось из заявки; если оно было больше плана, плановая часть обнулялась и расходы ложились на одну заявку. С 1 шт. по умолчанию база — плановый объём (в окне: «В расчёте 1 шт. · Прогноз 5 шт. · База 6 шт.»).
- **«Не делить расходы».** Руководитель (право «Изменение волн») может отметить в окне расчёта «Не делить расходы». Расчёт остаётся привязан к волне, но все общие расходы волны и таможенный сбор ложатся только на него: другие заказы и плановый объём их не делят. Отметка сохраняется в расчёте (`snapshot.wave.divided = false`) и переходит в новую версию.
- **Красный флажок** рядом с названием позиции в окне расчёта означает, что по этой позиции квоты уже записан расчёт. Подсказка флажка называет номер и дату последнего расчёта.

## Таможенный сбор колонок отменяет остальные сборы

Если в волне есть колонки (группа с фиксированным сбором 73 800 ₽), платится только этот сбор: он делится между позициями «Колонка», а сбор по шкале для других групп не начисляется — позиции других групп сбором не облагаются. В окне расчёта под базой волны это написано прямо. Если колонок в волне нет, сбор по шкале считается как раньше. Сохранённые расчёты и выпущенные КП не меняются.

## Загрузка квот: 40 позиций, загрузилось 38

Проверили файл «Шаблон_квот (3).xlsx»: на листе «Квоты» 38 строк, позиций заявки 7 и 21 в нём нет (нумерация идёт 6 → 8 и 20 → 22). Импорт загрузил все строки файла. Чтобы такое было видно сразу, проверка файла квот теперь пишет: «Строк в файле: 38. В заявке позиций: 40. Без строки в файле остались позиции заявки: 7, 21».

Большие файлы проверены автотестом: 2 000 строк квоты проверяются и записываются полностью (около 4 секунд на тестовой базе), лимит файла — 10 000 строк.

## Задачи: фильтры и группировка

Над списком задач — строка фильтров: **Задача** (поиск по названию), **Срок** (просрочено, сегодня, завтра, на этой неделе, позже, завершены и отменены), **Исполнитель** (первым — «Мои задачи»), **Состояние** (в том числе «Открытые»), **Приоритет**. Кнопка «Сбросить» очищает фильтры.

**Группировка:** по сроку (по умолчанию), по исполнителю, по клиенту, по состоянию, по приоритету или без группировки. У каждой группы заголовок с числом задач во всей выборке. У задачи по заявке в колонке «Клиент» показан клиент заявки и её номер. Браузер запоминает выбранные фильтры и группировку. Ссылка «Просроченные задачи» с рабочего стола открывает список с фильтром «Просрочено».

## API

- `POST /requests/{id}/calculations` и `/preview`: новое поле `divide_wave_expenses` (по умолчанию `true`; `false` требует права `waves.write`). Без `quantity` позиция считается как 1 шт. Запись расчёта новой методики без `delivery_days` отклоняется с кодом `DELIVERY_DAYS_REQUIRED`; `snapshot.delivery_days` больше не заполняется из квот.
- `snapshot.wave_distribution.customs_fee_scale_waived` — сбор по шкале не начислен из-за колонок.
- `GET /requests/{id}/quote-items`: у позиции новое поле `last_calculation` (`id`, `number`, `created_at`) или `null`.
- Проверка импорта квоты: в `summary` новые поля `request_positions` и `missing_positions`.
- `GET /tasks`: новые параметры `assignee_id`, `priority`, `due` (`overdue|today|tomorrow|week|later|closed`), `client_id`, `status=active`, `group` (`due|assignee|client|status|priority`). С `group` ответ содержит `groups` (`key`, `label`, `count`), а задачи — поле `group`. У задачи новые поля `client_id`, `request_number`, `due_group`; `client_name` заполняется и для задач по заявке.
- `analytics.reports` требуется для `/analytics/manufacturers`, `/analytics/suppliers`, `/analytics/suppliers/{id}`, `/analytics/invoices` и `/analytics/export.xlsx`.
