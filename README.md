# Реактив CRM — промежуточная передача проекта

Снимок разработки от **15 сентября 2026 года**. Это текущий исходный код и собранный интерфейс, а не завершённая приёмка по ТЗ. Детали проверки и незавершённые работы перечислены в `docs/INTERIM-HANDOFF.md`.

## Что находится в проекте

- `backend/` — Python 3.13, FastAPI, SQLAlchemy, PostgreSQL; миграции Alembic и тесты.
- `frontend/` — React, TypeScript, Vite; русскоязычный интерфейс. В передаваемый архив включена свежая сборка `frontend/dist/`.
- `docs/` — архитектура, API, модель данных, требования и исходные тексты ТЗ/промпта.
- `docker-compose.yml` — PostgreSQL, ClamAV, API, worker, миграции и веб-сервер.
- `scripts/init-env.py` — создание локальных настроек со случайными паролями без перезаписи существующего файла.

В исходниках есть пользователи и роли, контрагенты, обзвон, задачи, заявки и позиции, каталог, запросы поставщикам и квоты, настраиваемые расчётные профили, КП и счета, оплаты, согласования, волны поставок, чаты, вложения, импорт XLSX, отчёты и фоновые операции. Наличие модуля не означает завершённую проверку всех требований к нему.

## Локальный запуск из распакованного архива

Нужны Docker Compose, Python 3.13, Node.js 24 и pnpm 11.19.0. Команды выполняются из корня проекта. Установка зависимостей и первое получение Docker-образов требуют интернета.

```bash
# Только в новом каталоге, где ещё нет .env:
python3 scripts/init-env.py

docker compose up -d db clamav
python3.13 -m venv .venv
.venv/bin/pip install -r backend/requirements.lock
PYTHONPATH=backend .venv/bin/alembic -c backend/alembic.ini upgrade head
pnpm --dir frontend install --frozen-lockfile
```

Последняя миграция защиты истории включена в снимок, но ещё не прошла отдельную проверку в PostgreSQL. Не применяйте этот промежуточный снимок к рабочей базе с важными данными.

Создайте первого пользователя в новой базе. Адрес ниже — пример локального логина; отправки письма нет. Флаг `--all-roles` совмещает все роли для владельца, проверяющего систему.

```bash
PYTHONPATH=backend .venv/bin/python -m app.bootstrap --email admin@example.com --name 'Владелец проекта' --all-roles --credentials-file .runtime/access.txt
```

Затем запустите три процесса в отдельных терминалах:

```bash
PYTHONPATH=backend .venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

```bash
PYTHONPATH=backend .venv/bin/python -m app.communication.worker --interval 3
```

```bash
pnpm --dir frontend dev
```

Интерфейс: <http://127.0.0.1:5173>. API: <http://127.0.0.1:8000/api/docs>. Логин и пароль новой учётной записи находятся в `.runtime/access.txt`.

Если вы продолжаете работу в исходном каталоге разработчика, сохраните имеющиеся `.env`, `.runtime/` и Docker volumes. Они не входят в архив. Не создавайте заново существующего пользователя.

Полный контейнерный вариант описан в compose (`docker compose up --build -d`), но сборка и сквозной запуск этого варианта ещё не проверены. В контейнерном варианте вложения хранятся в volume `files-data`; локальная папка `.runtime/files` автоматически туда не переносится.

## Проверки

```bash
# Серверные проверки без подключения к PostgreSQL:
PYTHONPATH=backend .venv/bin/pytest backend/tests -m 'not postgres' -q

# Отдельные конкурентные проверки, требуют PostgreSQL:
PYTHONPATH=backend .venv/bin/pytest backend/tests/test_postgres_commerce.py -q

# Сборка интерфейса:
pnpm --dir frontend build
```

В момент передачи: **33 серверных теста прошли; TypeScript и сборка Vite прошли**. Остальные ограничения и исторический результат PostgreSQL-тестов приведены в протоколе передачи.

## Данные и настройки

Пароли, `.env`, пользовательские вложения, содержимое PostgreSQL и установленные зависимости в архив не включены. Архив является передачей кода, а не резервной копией рабочей среды.

Формулы, ставки, валюты, порог финансирования, шаблоны и права задаются пользователем. Условный финансовый пример предназначен для проверки арифметики; он не утверждает налоговые правила компании.

`scripts/backup.sh` и `scripts/restore.sh` в этом снимке **не готовы к использованию**: их обработчик `scripts/recovery.py` ещё не реализован.
