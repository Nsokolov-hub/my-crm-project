# Общение, вложения и очередь

Все маршруты под `/api/v1`, требуют активного сеанса; команды — CSRF. Создание чата, отправка сообщения и загрузка файла требуют `Idempotency-Key`. В личную переписку допускаются только участники, включая пользователей с административными правами. Участник чата заявки при каждом чтении и записи обязан сохранять право чтения заявки. В чате волны дополнительно проверяется владелец волны или область `all` для `waves.write`/`requests.read`.

| Метод и путь | Тело / параметры | Результат |
|---|---|---|
| GET /chats | page, page_size, q, entity_id | Доступные чаты, участники, unread, read_sequence |
| POST /chats | title, kind: direct/group/request/wave, member_ids, entity_id? | Чат; автор добавляется автоматически. Личный диалог пары единственный |
| GET /chats/{id} | — | Чат и текущие участники |
| PATCH /chats/{id} | title, version | Изменение названия создателем |
| POST /chats/{id}/members | user_id, version, history_acknowledged:true | Добавление создателем; новый участник получает всю историю. UI до подтверждения показывает предупреждение |
| DELETE /chats/{id}/members/{user_id} | version в query | Исключение создателем; доступ пропадает сразу. Состав личного диалога неизменяем |
| GET /chats/{id}/messages | after: sequence либо id сообщения, limit<=100 | items, next_cursor, has_more, last_sequence, read_sequence, unread |
| POST /chats/{id}/messages | content, file_ids?, mention_ids?, document_refs?:[{kind:document/quote/calculation,id}] | Стабильные id и sequence; один результат при повторах |
| POST /chats/{id}/read | through?: последний показанный sequence | Прочитанное продвигается только вперёд; отсутствие through означает весь текущий чат |
| GET /notifications | read?, page, page_size | Только личные уведомления и счётчик unread |
| POST /notifications/{id}/read | — | Личное уведомление прочитано |
| POST /files | multipart file, entity_type, entity_id, classification | Метаданные, status=quarantined, sha256; путь хранилища не возвращается |
| GET /files | entity_type, entity_id, page, page_size | Доступные файлы объекта |
| GET /files/{id} | — | Метаданные и текущий статус проверки |
| GET /files/{id}/download | — | Только clean + доступ объекта/категории + exports.download; аудит скачивания |

Объекты вложения: request/client/chat/wave/quote/calculation/document. Категории: `general`, `purchase`, `calculation`, `reward`, `profit`; последние четыре требуют соответствующего финансового права. Вложения квоты обязательно purchase, расчёта — calculation. Ссылки и вложения проверяются по исходному объекту при каждом чтении, включая повтор отправки после смены роли. Известные по SHA-256 копии финансовых файлов и файлов другого чата нельзя перезагрузить с расширением доступа; используется исходная ссылка. Автоматического распознавания финансового смысла произвольного нового файла нет: пользователь выбирает категорию, а объекты квоты/расчёта задают её обязательно.

Разрешены PDF, PNG, JPEG, GIF, UTF-8 TXT/CSV, XLSX/DOCX без макросов и шифрования. Фактическая сигнатура/структура сопоставляется с расширением и MIME. HTML/SVG/скрипты/исполняемые файлы отклоняются; архивы не распаковываются на диск. Начальный предел 25 МБ; `file_policy.max_file_size` в настройках допускает 1 КБ–100 МБ. Статусы: quarantined → clean/infected; после исчерпания повторов scan_failed. До окончательного clean скачивание запрещено. Файлы всегда выдаются вложением с `nosniff`, `sandbox`, `private,no-store` и проверкой SHA-256.

Worker запускается `PYTHONPATH=backend .venv/bin/python -m app.communication.worker`; `--once` выполняет одну итерацию. Типы очереди: file.scan, notification, task.reminder, import.confirm. Событие и бизнес-изменение сохраняются одной транзакцией; обработка использует `FOR UPDATE SKIP LOCKED`, вложенную транзакцию обработчика, до пяти попыток с задержкой 2–300 секунд. Неуспех виден как failed, технические сообщения и содержимое события не попадают в уведомления. При завершении работы процесса незавершённая транзакция откатывается, событие остаётся доступно для повторной обработки.

Напоминания настраиваются ключом `task_reminders`: enabled, timezone (IANA), lead_working_days (0–30), lead_minutes (необязательное переопределение), working_days ([0…6], понедельник=0), holidays (ISO dates). Начальное поведение: за один рабочий день, Пн–Пт, Europe/Moscow; отдельное событие при просрочке. Переназначение/перенос срока создаёт новую актуальную контрольную точку. Завершённые, отменённые и утратившие актуальность задачи не порождают напоминания; повтор обработки не дублирует уведомление.

Сообщения хранятся обычным текстом, UI не должен отображать их через HTML. Непрочитанное снимается отдельной командой после фактического отображения; загрузка истории сама по себе ничего не отмечает прочитанным. Редактирование/удаление сообщений, полнотекстовый поиск вложений, голос и видео в эту реализацию П1 не входят.
