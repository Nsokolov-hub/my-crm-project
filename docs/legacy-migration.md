# Стратегия и реестр переноса исторических данных (R13, S17)

## Реестр источников

| Источник (Система/Файл) | Сущности CRM | Внешний ID (External ID) | Владелец колонок | Стратегия обновления | Контрольное число (Сверка) |
|---|---|---|---|---|---|
| Учётная система (1С/SAP) | `Counterparty`, `Seller` | `external_id` (ИНН/KPP/GUID) | Бухгалтерия | Идемпотентный поиск по `external_id` / имени. CRM не перезаписывает реквизиты, пришедшие из системы. | Количество контрагентов и продавцов. |
| Сотрудники компании | `User` | `legacy_id`, `email` | Отдел кадров / ИТ | Исторические сотрудники создаются неактивными (`active=False`) с рандомным паролем для сохранения авторства сделок. | Количество созданных/сопоставленных пользователей. |
| Историческая БД заявок | `Request` | `legacy_id`, `number` | Отдел продаж | Идемпотентная вставка по номеру. Обновление закрытых сделок запрещено. | Кол-во заявок, суммы. |
| Старые расчёты (Excel/CRM) | `Calculation`, `CommercialDocument` | `number` (счёта/КП) | Коммерческий отдел | Архивирование. Старые расчеты получают профиль `LEGACY_ARCHIVE` и `snapshot["is_legacy_archive"] = True` без принудительного пересчета. `valid_until` при отсутствии берется как дата счета + 30 дней. | Баланс дебиторской задолженности по валютам. |
| Выписки банка | `Payment`, `PaymentAllocation` | `external_id` (УИН платежа) | Бухгалтерия | Идемпотентный импорт в привязке к `seller_id`. Платежи без явной ссылки на счет фиксируются как авансы без фиктивных привязок к чужим счетам. | Обороты за период по валютам, неразнесенные авансы. |

## Строгий контракт входных данных (R13)

1. **Запрет подмены неизвестных дат константами:**
   Каждая запись заявки и платежа должна содержать явную дату в формате ISO (`YYYY-MM-DD` или `YYYY-MM-DDTHH:MM:SSZ`). Если дата отсутствует или повреждена, запись отклоняется с занесением в отчет расхождений (`discrepancies`).
2. **Запрет связывания авансов с фиктивными счетами:**
   Если платеж является авансовым или в источнике не указана ссылка на счет (`invoice_number` / `invoice_legacy_id`), он сохраняется как подтвержденный платеж контрагента без распределения (`PaymentAllocation`). Создание фиктивных счетов или связывание с нерелевантными счетами строго запрещено.
3. **Сопоставление уволенных/исторических сотрудников:**
   Входящие сотрудники сопоставляются по email с существующими учетными записями. Новые исторические сотрудники создаются с флагом `active=False` и недоступным паролем, что позволяет сохранить полную целостность аудита и авторства в `Request.owner_id`, `CommercialDocument.author_id`, `Payment.declared_by`.
4. **Финансовые контрольные суммы:**
   По каждой валюте в миграционном пакете рассчитываются контрольные суммы:
   - `invoiced` — сумма выставленных счетов;
   - `paid` — сумма поступивших платежей;
   - `allocated` — сумма распределенных оплат по счетам;
   - `outstanding_receivables` — остаток дебиторской задолженности (`invoiced - allocated`);
   - `unallocated_advances` — остаток нераспределенных авансов (`paid - allocated`).

## CLI утилиты миграции (`scripts/migrate_legacy.py`)

Утилита поддерживает два режима выполнения и выгрузку подробного отчета аудита в JSON:

```bash
# 1. Пробный прогон с выгрузкой отчета (без изменений в БД, автоматический откат транзакции)
python3 scripts/migrate_legacy.py scripts/legacy_sample.json --dry-run --report reports/legacy_dry_run.json

# 2. Фактический перенос данных с сохранением в БД
python3 scripts/migrate_legacy.py scripts/legacy_sample.json --commit --report reports/legacy_commit.json
```

## Регламент переключения (Freeze/Delta)

1. **Dry-Run (Пробный прогон):**
   Из старой системы выгружаются данные (JSON/CSV). Запускается `scripts/migrate_legacy.py --dry-run --report <path>`. 
   Проверяется массив `discrepancies` и сходимость финансовых контрольных сумм с бухгалтерским балансом. При наличии замечаний источник корректируется до полного устранения расхождений.

2. **Freeze (Заморозка):**
   Остановка создания новых заявок в старой системе (обычно пятница вечер). Выгрузка финального полного слепка данных.

3. **Delta (Финальный перенос):**
   Запуск `scripts/migrate_legacy.py --commit --report <path>`. Сверка отчета о миграции с реестром.

4. **Ограничения и неизменность истории:**
   Старые расчёты вносятся в базу с профилем `LEGACY_ARCHIVE` и признаком `snapshot["is_legacy_archive"] = True`. CRM их не пересчитывает новыми шаблонами. 
   Любое изменение старой сделки требует создания нового расчёта по действующим правилам, что полностью соответствует требованиям неизменности истории (R01/R02).
